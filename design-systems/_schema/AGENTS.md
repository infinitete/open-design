# `_schema/` — design-system contracts

This directory codifies the structural contracts for design systems. The TypeScript schemas are the source of truth; `defaults.css` is a human-readable mirror of the A2 `fallback` fields (drift enforced by the A2-defaults-parity guard).

```
_schema/
├── manifest.schema.ts ← project manifest schema (TS, machine-enforced when present)
├── tokens.schema.ts   ← token schema re-export of packages/contracts/src/design-systems/token-schema.ts
├── defaults.css       ← A2 fallback values (CSS, human reference)
└── AGENTS.md          ← this file
```

Every bundled catalog entry ships `manifest.json` + `DESIGN.md` + `tokens.css`; the daemon keeps `DESIGN.md`-only discovery solely as a compatibility path for older or user-installed folders. Manifest shape is enforced by `scripts/check-design-system-manifests.ts`.

## Project package layout

Fixed v1 file names under `design-systems/<brand>/`: `manifest.json` (required), `DESIGN.md` (required), `tokens.css` (required), plus optional `design-tokens.json`, `tailwind-v4.css` (derived from `tokens.css`, never independent values), `components.html`, `components.manifest.json` (rebuildable cache — must match fresh derivation from `components.html` + `tokens.css`), `assets/`, `preview/`, `USAGE.md`, `fonts/`, `source/` (importer evidence).

Declared rich paths must be safe and present; JSON indexes must parse. These fields are runtime inputs: discovery consumes manifest metadata, prompt composition consumes usage/tokens/components/craft bindings, and package/static-file routes expose only declared preview and source files.

## Token layers

Artifacts are generated by pasting one brand's `:root` block into a single `<style>` with no global stylesheet alongside — so **every shared slot must be declared by every brand**, either as an independent value or (B-slot) as a `var(--sibling)` alias. Missing slots resolve to nothing and silently break artifacts.

| Layer | Who decides | If omitted | Examples |
| --- | --- | --- | --- |
| **A1** | brand | guard fails | `--bg`, `--fg`, `--accent`, `--font-display`, type scale, `--container-max` |
| **A2** | brand, with schema fallback | guard fails (until a derive script inlines `defaults.css`; contract unchanged) | `--motion-fast`, `--success`, `--space-4` |
| **B-slot** | brand or schema alias | guard fails — declare value or `aliasTo` verbatim (e.g. `--fg-2: var(--fg)`) | `--fg-2`, `--surface-warm`, `--border-soft` |

Brand-specific tokens outside the schema are **C-extensions** (`BRAND_EXTENSIONS` per brand, `BRAND_EXTENSION_PREFIXES` for families like `--tag-bg-*`). Promotion: C → B-slot/A2 when ≥2 brands declare the same name (B-slot needs a meaningful sibling alias, A2 a cross-brand fallback); B-slot → A2 when ≥2 brands bind it independently. No demotion — deprecate for one release, then delete everywhere in one PR.

## When NOT to add a token

Every new entry forces every brand to declare or alias it. Resist component-internal values (inline them), one-offs, speculative names, and anything already expressible via `color-mix(...)` over an existing token.

## Editing this directory

- Run `pnpm guard` and confirm every design-system sub-check passes.
- Added an A2 entry: mirror it in `defaults.css`, byte-equivalent to the `fallback`.
- Renamed a token: bump every brand's `tokens.css` and matching `components.html` `:root` in the same commit.
- Removed a token now used by one brand only: add it to that brand's `BRAND_EXTENSIONS` so the unknown-token guard passes.
