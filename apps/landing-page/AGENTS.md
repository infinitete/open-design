# apps/landing-page/AGENTS.md

Follow the root `AGENTS.md` and `apps/AGENTS.md` first. This file only
records module-level boundaries for `apps/landing-page/`.

## Purpose

Standalone static Astro marketing + public catalog site (Atelier Zero style).
It reads canonical repo content (`skills/`, `design-templates/`, `design-systems/`,
`craft/`, `plugins/`) at build time through Astro content collections
(`app/content.config.ts`, schemas stay loose `passthrough()` so vendored
upstream Markdown never breaks the build) and ships to Cloudflare Pages.
Catalog sources are never mirrored here — editing a `SKILL.md`/`DESIGN.md`/manifest
flows into the next build with no registration step.

Coupled sources: `design-templates/open-design-landing/example.html`
(homepage hero known-good rendering) and `design-systems/atelier-zero/DESIGN.md`
(token spec). `app/page.tsx` + `app/globals.css` are kept in lockstep with that
`example.html`; the rest of the app is not. Page data comes shaped from
`app/_lib/catalog.ts` — never re-parse Markdown in JSX. React is build-time
only (`renderToStaticMarkup`); output is static HTML/CSS plus a small inline script.

## Boundary constraints

- Must remain static Astro output. No `/api`, no daemon proxy.
- Must not import `@open-design/web|daemon|desktop|sidecar*|contracts`. No `src/` shell — source lives under `app/` (`app/_components/<name>.{tsx,astro}`).
- No non-Google web fonts. No committed local PNG mirrors under `public/assets/` (R2 + Cloudflare Image Resizing via `app/image-assets.ts`); `public/previews/` thumbnails are gitignored and regenerated by CI (`scripts/generate-previews.ts`).
- Visible "X skills / Y systems" counts must come from `getCatalogCounts()` — never hardcode.

## Deploy contract (staging → manual production)

Two Cloudflare Pages projects so a `main` push can never publish live:

- Staging `open-design-landing-staging` ← `landing-page-staging.yml` on push to `main`.
- Production `open-design-landing` ← `landing-page-production.yml`, **manual only** (`workflow_dispatch`, gate the `production` environment). No other workflow may name the production project.
- `landing-page-ci.yml` validates PR builds (+ per-PR preview on same-repo branches).

The staging workflow's `paths:` filter must cover every build-time reader
(`apps/landing-page/**`, `design-templates/**`, `skills/**`, `design-systems/**`,
`craft/**`, `templates/**`, `plugins/**`, manifests). A catalog-source push that
does NOT trigger staging means the filter drifted and the staged site silently
falls behind.

## Common commands

```bash
pnpm --filter @open-design/landing-page dev          # http://127.0.0.1:17574
pnpm --filter @open-design/landing-page typecheck
pnpm --filter @open-design/landing-page previews     # render thumbnails
pnpm --filter @open-design/landing-page build        # static export → out/
```

## When to update this app

- New top-level route group → Astro page under `app/pages/` + collection in `app/content.config.ts` + shaping function in `app/_lib/catalog.ts`, matching the existing index/detail/facet pattern.
- Canonical landing `example.html` gained a section → port it into `app/page.tsx` + `app/globals.css`.
- Non-Open-Design tenant re-brand → fork the app; do not parameterize for multi-tenancy.
